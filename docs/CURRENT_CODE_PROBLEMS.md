# Original Scaffold Audit and v0.1 Replacements

This is an audit of commit `b18e5f8` (the original scaffold), not a list of present files.  Each item records the observed behavior, why it made an SCF/DFT result unreliable or unusable, and the concrete v0.1 replacement.

| Original behavior (evidence) | Mathematical or software risk | v0.1 replacement |
| --- | --- | --- |
| Modules used bare imports such as `import system`, `import fft_grid`, and `import i_o`. | Import resolution depends on the current directory and fails or imports an unrelated module after installation. | Every package dependency uses relative imports (`from .… import …`); `pyproject.toml` declares `mini_dft` and a console entry point. |
| `scf.py` constructed `System = system.system('input.yaml')` and entered its SCF loop at import time. | Importing a library could start a calculation, print output, require a cwd-local file, or hang test discovery. | `SCFRunner.run()` is explicit; `mini_dft.__main__.main()` is the only CLI execution path, guarded by `if __name__ == "__main__"`. |
| `mini_dft/input.yaml` was empty and there was no package metadata. | There was no runnable configuration or reproducible installation route. | Validated example YAML files, `pyproject.toml`, `README.md`, and regression tests make installation and execution defined. |
| `i_o.py` functions (`get_lattice`, `get_atoms`, …) returned numeric placeholders 1 through 10. | A nominal `system` contained meaningless scalars rather than physical input, without schema or unit validation. | `load_system` parses YAML into typed `SystemConfig`, `SCFConfig`, `DOSConfig`, and potential configurations with field-path errors and unit conversion. |
| `ionic_potential.ionic_potential`, `hartree.hartree`, and `xc.xc` were placeholders or absent physics. | No meaningful external, electrostatic, or exchange-correlation operator was available. | `build_ionic_potential`, `hartree_from_density`, and `lda_pz81` implement finite periodic local model fields and return structured results. |
| No lattice row/column convention was established. | Reciprocal vectors, fractional coordinates, and volume-dependent operations can be transposed silently. | YAML rows are explicitly transposed into column-oriented `Lattice.A`; `B=2πA^{-T}` is validated and documented. |
| `kinetic_energy(c, k)` used `c * 0.5 * (k + c)**2`. | The coefficient `c` was incorrectly used as a reciprocal vector; the kinetic operator was nonlinear and dimensionally wrong. | `basis.kinetic_energies = 0.5 * |G|²` is precomputed, and `Hamiltonian.apply` multiplies it elementwise by coefficients. |
| There was no reciprocal-vector enumeration, cutoff sphere, or coefficient-to-grid index map. | The length of a coefficient vector had no physical relation to a plane-wave basis or FFT locations. | `PlaneWaveBasis.from_cutoff` enumerates integer `g_indices`, Cartesian `g_vectors`, and cutoff energies; `FFTGrid` maps signed indices into its cube. |
| `fft_grid` had no specified physical scaling. | Parseval normalization, charge, density, potential matrix elements, and energy units were undefined. | `FFTGrid` provides separate normalized wavefunction and scalar-field transforms and tests their round trips and quadrature identities. |
| `eigensolver.get_eigenvalues` created a `LinearOperator(dtype=float)` while comments acknowledged complex wavefunctions. | SciPy could discard imaginary parts and violate Hermiticity for a complex plane-wave problem. | `Hamiltonian.as_linear_operator` and the eigensolver use `np.complex128`, normalize states, and check unshifted residuals. |
| The SCF driver set `N = 1` independently of the basis and bands. | Operator dimension, number of eigenpairs, and physical occupancy were inconsistent. | Basis dimension is `basis.npw`, requested `bands` is validated against it, and integer occupations derive from `electrons`. |
| The loop `for ik in System.kpoints` assumed an iterable list returned from a placeholder I/O function. | K-point state was neither represented nor weighted; an integer placeholder would fail at runtime. | v0.1 deliberately implements one documented Gamma-point calculation and does not pretend to provide k-point sampling. |
| Density was accumulated over `range(N)` rather than well-defined occupied bands and omitted an occupation object. | Density could exclude states, double-count implicitly, and violate the electron-number integral. | `density_from_coefficients` contracts `(bands, npw)` coefficients with explicit 0/2 occupations and tests `density_integral == electrons`. |
| `density_old` was never advanced after mixing and `Potential` was computed once before the loop. | The loop did not form a self-consistent fixed point; every solve saw stale state. | `SCFRunner` rebuilds Hartree/XC/effective potential from each input density and assigns the mixed density for the next iteration. |
| The printed `E_total` was a sum of eigenvalues. | Eigenvalue sums contain Hartree/XC double counting and are not the model energy. | `calculate_energy` evaluates `T_s + E_ext + E_H + E_xc`; `eigenvalue_energy` is retained only as a corrected consistency diagnostic. |
| There was no occupation policy, charge renormalization, convergence-energy test, result output, or input boundary validation. | Invalid systems could run, charge could drift, termination had no reliable condition, and results were not portable/reloadable. | v0.1 validates inputs, uses charge-preserving linear mixing, checks density and energy tolerances with a consistency pass, and writes YAML/CSV/NPZ diagnostics. |
| The original test files were empty (`tests/test.py`) or offered no executable coverage of the scaffold. | No numerical convention or end-to-end behavior was protected from regression. | The v0.1 suite covers lattice/basis/FFT/physics/SCF/CLI invariants and executes both repository examples. |

The replacements intentionally remain small and educational.  They make the program internally defined and testable; they do not convert its model potentials or Gamma-only LDA treatment into a predictive materials code.
